# 动画诊断与精修

以 `feat/lucky-actions-trio` / PR #6 的 `13d0823` 为基线。复查了床铺的独立图层、40×60 人物图集、40×40 Lucky 图集以及 Phaser 场景的动作调度。以下估算以本轮工作量为单位。

| 优先级 | 问题与根因 | 涉及代码与素材 | 处理方式与预计工作量 |
| --- | --- | --- | --- |
| P0 | 上床前站在床边，随后用同一帧内移，到达后直接转躺。现有图集缺少坐稳、抓取与转身 | `BedController.ts`、`bedState.ts`、原 `*-sleep.png` | 重绘每人 8 个关键姿势，依次走路、侧坐、伸手、拉被、转身、后仰、拉回、闭眼。约 30% |
| P0 | 盖被靠整张被面移位并裁切，床尾纹理跟着移动，图层里没有背面 | `BedQuilt.ts`、`quilt-*.png` | 复用原被面纹理，制作翻折帧、里布和压褶阴影。两侧有独立控制，手掌单独越过被缘。约 20% |
| P1 | 抬起时人物先换到中间抱姿，Lucky 再朝固定点移动。手的遮挡裁片在弯腰帧为空，放下目标可能超出双臂可及范围 | `PetActionDirector.ts`、`HumanPetAnimator.ts`、`petContact.ts`、`*-arms.png` | 用同一进度编排弯腰、抬升和托抱，测量角色专用接触位置，补前景手腕遮挡。复用现有抱持步态和托抱帧。约 18% |
| P1 | 上床只有站前蹲姿和单次腾空帧，抛物线经过床沿时没有伸腿、前爪接触与后腿跟进 | `TrioSleepController.ts`、`lucky-performance.png` | 重绘 8 个四肢关键姿势，分配蓄力、蹬地、腾空、下降、前爪承重和后腿收稳。床垫轻微压缩后回弹。约 16% |
| P1 | Lucky 钻被时中央覆盖片与原被面同时显示，折痕不随身体位置移动 | `TrioSleepController.ts`、`BedQuilt.ts`、旧 `quilt-center.png` | 人物两侧保持独立，三人流程临时换同一块完整被面。中部折痕随 Lucky 推进，身体与头部分别遮挡。约 9% |
| P2 | 抚摸共用抱起接触点。叼球每方向只用一个偏移加通用摆动。狗窝从站立直接变为趴卧，睡眠循环轮换的姿态差异过大 | `petContact.ts`、`interactionAnchors.ts`、`BallAttachment.ts`、`PetActionDirector.ts` | 复用动作素材。分别实测触摸锚点与运动帧嘴部偏移，保留低头放球。加趴卧过渡与低幅度睡眠变化。约 7% |

`src/assets/bed/*-bed.png` 为 320×60 的 8 帧人物图集。独立左右翻折为 408×124 的 16 帧图集，中央抬起为 816×148 的 16 帧图集，中央移动褶皱为 816×296 的 32 帧图集。Lucky 起跳图集为 320×40 的 8 帧。保留来源图与两个离线打包脚本，游戏使用打包后的最近邻 PNG。

验收关注准备、接触、完成三个阶段。重点放慢看手掌是否跟上被角或 Lucky 的身体，前爪是否先触到床面，夜间被子遮挡是否正确，以及取消后角色是否恢复控制。半速播放器使用同一段真实 Phaser 录屏。独立入睡、起床与三人动作仍可在试玩中用菜单触发。

补绘采用 AI 辅助绘制和离线像素整理，动作仍由离散关键姿势衔接。贴靠家具时游戏会寻找短距离的安全交互站位，空间不足时无法发起抱放。球和手掌属于基于游戏画面量测的锚点，视觉自然程度仍需人工验收。没有在真实 iPad Safari 上完成设备验收。
