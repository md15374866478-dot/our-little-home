# Lucky 上床后的绿色方块

Chromium 实机复现时，逐帧记录 Lucky 主精灵、被面和遮挡精灵的纹理键、帧号、深度、可见性与位置。床面行走阶段使用 `lucky` 的四向图集，钻被使用 `lucky-performance`，切换过程中的图块都是有效的 40×40 原创 Lucky 帧。绿色物体来自深度 12 的床铺中央被面精灵 `fold-travel`。它在 `raiseAt()` 切换帧时沿床铺移动。

旧打包器在一条水平线上从加亮切到变暗，并向上取样原被面。硬边阴影与重采样后的格纹合成明显的暗绿色块。旧矩形遮罩同时快速裁掉 Lucky 上半身，因此暗块看起来像替换了 Lucky。遮罩图形是 Phaser 几何遮罩，没有出现在场景显示列表。逐帧记录没有发现占位图、路径标记或越界帧。

修复只重打包中央移动褶皱。新帧保留源像素和透明边界，使用渐入渐出的弧形光影。两侧翻折、中央被沿抬起和人物动画图集维持原样。新 `WALK_BED` 阶段在两段移动开始前播放已加载的行走帧，随后面向枕头，从被缘逐渐遮住 Lucky 的头、肩和后爪。入睡后前景身体精灵退出，起床时重新出现。床沿仍挡在前景身体之前。

`luckyBedFrames.ts` 会在启动动作前检查三张图集及所需帧的 40×40 裁切范围。单元测试覆盖缺失图集、缺失落地帧及裁切越界。Chromium 脚本 `scripts/qa-lucky-bed-render.cjs` 检查实际解码后的精灵像素、所有褶皱帧、各阶段真正渲染过的帧、遮挡推进及起床清理。验收录像来自同一条完整实机流程，可在播放器以 1 倍或 0.5 倍播放。
