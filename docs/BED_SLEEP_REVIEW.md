# Phase 3.4.1 双人睡眠实机验收

当前分支保留 Phase 3.4 尚未提交的完整房间镜头和沙发前沿调整。本轮只新增床铺与睡眠资源，不更改房间底图、庭院 PNG 或碰撞网格。

## 资源与渲染

`src/assets/bed/` 包含透明 RGBA 床架、床垫、左右枕头、床沿（各 128×118，统一局部原点）；两侧被子各 51×62；马硕、门都各一张 160×60 的躺卧图集（4 帧，单帧 40×60）。源图为 AI 辅助原创素材，打包脚本 `scripts/prepare_bed_v34.py` 离线处理尺寸与二值 Alpha，消除半透明光晕。原有认可的四方向图集未改。

床铺在原位置上以独立图层替换原底图中的床内区域。旧静态床被和床沿前景不再加载到当前场景。深度顺序为房间、床架、床垫、枕头、人物、两侧被子、床沿。被子上下沿通过移动与裁片高度形成掀开/盖回过程；角色不旋转、不压扁、不缩小、不通过透明度消失。闭眼帧循环和被子 1 像素起伏用于呼吸。

## 操作与状态

右上角「与门都互动」菜单可滚动：一起睡觉、马硕先睡、门都先睡、马硕起床、门都起床、一起起床。按方向键会先让马硕起床。其他互动会先让两人安全下床，再执行原动作。

`BedController.ts` 实际使用 `BedState`，每人拥有独立 revision、寻路、掀被、进入、盖被、睡眠、起床及返回床边流程。旧异步完成事件无法覆盖取消后的新状态。门都的自主行为在床铺被占用期间暂停，释放后恢复冷却计时。普通进出地图仍使用既有场景协调。

`/bed-review/` 提供真实 Phaser 游戏的床边、钻入、双人睡眠、单人睡眠和一人起床截图，以及连续 MP4 演示。录像覆盖马硕先睡、门都后睡、马硕单独起床、全部起床，以及两人同时进入和醒来。另以浏览器检查反向先后顺序和进入途中取消。

## 边界

素材是可玩的 AI 辅助版本，非像素画师逐帧修稿；入睡为坐入、后仰、躺卧、呼吸四帧，动作细腻度仍可提高。真实 iPad Safari 的持续触控与播放表现需设备验收。室内当前使用等比适配固定镜头，非整数倍率下最近邻采样可能出现像素宽度不均，未使用模糊滤镜。
